## 1. Insiemi, parametri e variabili decisionali

**Insiemi**
- I = {1, 2, 3, 4, 5, 6, 7, 8} — indice dei progetti P1,...,P8

**Parametri**
- v_i = valore del progetto i (30, 24, 35, 28, 33, 26, 38, 21)
- b_i = budget richiesto dal progetto i (20, 18, 27, 24, 22, 19, 30, 15)
- p_i = personale richiesto dal progetto i (4, 3, 5, 4, 4, 3, 5, 2)
- B = 100 (budget massimo disponibile)
- L = 18 (personale massimo disponibile)
- D = {1, 3, 7} (insieme dei progetti "digitali")

**Variabili decisionali**
- x_i ∈ {0,1} per i ∈ I, con x_i = 1 se il progetto i è selezionato, 0 altrimenti

## 2. Formulazione matematica

**Funzione obiettivo**

max Z = Σ_{i∈I} v_i · x_i

**Vincoli**

1. Budget: Σ_{i∈I} b_i · x_i ≤ B
2. Personale: Σ_{i∈I} p_i · x_i ≤ L
3. Precedenza P5→P2: x_5 ≤ x_2
4. Precedenza P7→P3: x_7 ≤ x_3
5. Incompatibilità P4-P6: x_4 + x_6 ≤ 1
6. Almeno un progetto digitale: Σ_{i∈D} x_i ≥ 1  (x_1 + x_3 + x_7 ≥ 1)
7. Almeno tre progetti totali: Σ_{i∈I} x_i ≥ 3
8. Dominio: x_i ∈ {0,1} ∀ i ∈ I

## 3. Codice Python (gurobipy)

```python
import gurobipy as gp
from gurobipy import GRB

# Dati
projects = [1, 2, 3, 4, 5, 6, 7, 8]
value = {1:30, 2:24, 3:35, 4:28, 5:33, 6:26, 7:38, 8:21}
budget = {1:20, 2:18, 3:27, 4:24, 5:22, 6:19, 7:30, 8:15}
personnel = {1:4, 2:3, 3:5, 4:4, 5:4, 6:3, 7:5, 8:2}

B_max = 100
L_max = 18
digital = [1, 3, 7]

# Modello
m = gp.Model("Selezione_Portafoglio_Progetti")

# Variabili decisionali
x = m.addVars(projects, vtype=GRB.BINARY, name="x")

# Funzione obiettivo
m.setObjective(gp.quicksum(value[i] * x[i] for i in projects), GRB.MAXIMIZE)

# Vincolo di budget
m.addConstr(gp.quicksum(budget[i] * x[i] for i in projects) <= B_max, name="Budget")

# Vincolo di personale
m.addConstr(gp.quicksum(personnel[i] * x[i] for i in projects) <= L_max, name="Personale")

# P5 richiede P2
m.addConstr(x[5] <= x[2], name="P5_richiede_P2")

# P7 richiede P3
m.addConstr(x[7] <= x[3], name="P7_richiede_P3")

# P4 e P6 incompatibili
m.addConstr(x[4] + x[6] <= 1, name="P4_P6_incompatibili")

# Almeno un progetto digitale tra P1, P3, P7
m.addConstr(gp.quicksum(x[i] for i in digital) >= 1, name="Almeno_un_digitale")

# Almeno tre progetti totali
m.addConstr(gp.quicksum(x[i] for i in projects) >= 3, name="Almeno_tre_progetti")

# Risoluzione
m.optimize()

# Output risultati
status = m.Status
if status == GRB.OPTIMAL:
    obj_val = m.ObjVal
    variables = {f"x_{i}": x[i].X for i in projects}
    status_str = "OPTIMAL"
else:
    obj_val = None
    variables = {}
    status_str = str(status)

import json
print("SOLUTION_JSON=" + json.dumps({
    "status": status_str,
    "objective": obj_val,
    "variables": variables
}))
```

## 4. Sintesi della soluzione

Il modello seleziona il sottoinsieme di progetti che massimizza il valore complessivo rispettando i vincoli di budget (≤100), personale (≤18 unità), le relazioni di precedenza (P5 richiede P2, P7 richiede P3), l'incompatibilità tra P4 e P6, l'obbligo di includere almeno un progetto digitale (P1, P3 o P7) e la scelta di almeno tre progetti in totale.

Risolvendo il problema con Gurobi si ottiene una soluzione ottima intera che identifica quali progetti attivare (x_i = 1) per massimizzare il valore atteso Z, rispettando simultaneamente tutti i vincoli di risorse e di business sopra descritti. Il codice fornito costruisce il modello IP binario, lo risolve e stampa lo stato del solver, il valore ottimo della funzione obiettivo e il valore di ciascuna variabile decisionale x_i (incluse quelle nulle) nel formato JSON richiesto.
