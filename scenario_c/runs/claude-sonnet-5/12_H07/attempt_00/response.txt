## 1. Insiemi, parametri e variabili

**Insiemi**
- I = {A,B,C,D,E,F} — fornitori
- K = {C1,C2,C3} — componenti
- S ⊆ I×K — coppie (fornitore, componente) effettivamente fornibili (celle non “—”)

**Parametri**
- demand_k : fabbisogno del componente k (80,70,60)
- fixed_i : costo fisso di attivazione del fornitore i
- cap_i : capacità totale (su tutti i componenti) del fornitore i
- risk_i : coefficiente di rischio del fornitore i
- cost_{i,k} : costo unitario per (i,k)∈S
- qual_{i,k} : qualità per (i,k)∈S
- M_{i,k} = min(cap_i, demand_k) — big‑M per il legame quantità/uso

**Variabili decisionali**
- x_{i,k} ∈ ℤ≥0, per (i,k)∈S — quantità acquistata
- z_{i,k} ∈ {0,1}, per (i,k)∈S — 1 se il fornitore i è usato per il componente k
- y_i ∈ {0,1}, per i∈I — 1 se il fornitore i è attivato

## 2. Formulazione matematica

Minimizzare
```
Σ_{(i,k)∈S} cost_{i,k} · x_{i,k}  +  Σ_{i∈I} fixed_i · y_i
```

Soggetto a:

1. Domanda esatta:  
   Σ_{i:(i,k)∈S} x_{i,k} = demand_k   ∀k∈K

2. Attivazione quantità/uso:  
   x_{i,k} ≤ M_{i,k}·z_{i,k}   ∀(i,k)∈S  
   x_{i,k} ≥ 10·z_{i,k}    ∀(i,k)∈S

3. Multisourcing minimo:  
   Σ_{i:(i,k)∈S} z_{i,k} ≥ 2   ∀k∈K

4. Capacità complessiva per fornitore:  
   Σ_{k:(i,k)∈S} x_{i,k} ≤ cap_i · y_i   ∀i∈I

5. Coerenza uso‑attivazione:  
   z_{i,k} ≤ y_i   ∀(i,k)∈S

6. Numero massimo fornitori attivi:  
   Σ_{i∈I} y_i ≤ 4

7. Almeno uno tra A e B:  
   y_A + y_B ≥ 1

8. Qualità media minima:  
   Σ_{i:(i,k)∈S} qual_{i,k}·x_{i,k} ≥ 95·demand_k   ∀k∈K

9. Rischio totale massimo:  
   Σ_{(i,k)∈S} risk_i·x_{i,k} ≤ 580

10. Domini:  
    x_{i,k}∈ℤ≥0, z_{i,k}∈{0,1}, y_i∈{0,1}

## 3. Codice Python (gurobipy)

```python
import gurobipy as gp
from gurobipy import GRB

suppliers = ['A','B','C','D','E','F']
components = ['C1','C2','C3']

demand = {'C1':80,'C2':70,'C3':60}
fixed  = {'A':120,'B':140,'C':100,'D':150,'E':90,'F':110}
cap    = {'A':100,'B':110,'C':90,'D':120,'E':80,'F':95}
risk   = {'A':2,'B':3,'C':1,'D':4,'E':2,'F':3}

cost = {
    ('A','C1'):9, ('A','C2'):12, ('A','C3'):11,
    ('B','C1'):10,('B','C2'):9,  ('B','C3'):12,
    ('C','C1'):11,('C','C2'):10, ('C','C3'):9,
                 ('D','C2'):11, ('D','C3'):10,
    ('E','C1'):12,('E','C2'):8,
    ('F','C1'):10,               ('F','C3'):8,
}

quality = {
    ('A','C1'):96, ('A','C2'):94, ('A','C3'):95,
    ('B','C1'):93, ('B','C2'):97, ('B','C3'):92,
    ('C','C1'):98, ('C','C2'):95, ('C','C3'):96,
                    ('D','C2'):94, ('D','C3'):93,
    ('E','C1'):97, ('E','C2'):98,
    ('F','C1'):94,                ('F','C3'):98,
}

S = list(cost.keys())

m = gp.Model("H07_sourcing")
m.Params.OutputFlag = 0

x = m.addVars(S, vtype=GRB.INTEGER, lb=0, name="x")
z = m.addVars(S, vtype=GRB.BINARY, name="z")
y = m.addVars(suppliers, vtype=GRB.BINARY, name="y")

# 1. Domanda esatta
for k in components:
    m.addConstr(
        gp.quicksum(x[i,k] for i in suppliers if (i,k) in cost) == demand[k],
        name=f"demand_{k}"
    )

# 2. Legame quantità-uso e minimo 10 unità
for (i,k) in S:
    M_ik = min(cap[i], demand[k])
    m.addConstr(x[i,k] <= M_ik * z[i,k], name=f"bigM_{i}_{k}")
    m.addConstr(x[i,k] >= 10 * z[i,k], name=f"min10_{i}_{k}")

# 3. Almeno 2 fornitori per componente
for k in components:
    m.addConstr(
        gp.quicksum(z[i,k] for i in suppliers if (i,k) in cost) >= 2,
        name=f"multisource_{k}"
    )

# 4. Capacità complessiva per fornitore
for i in suppliers:
    m.addConstr(
        gp.quicksum(x[i,k] for k in components if (i,k) in cost) <= cap[i]*y[i],
        name=f"cap_{i}"
    )

# 5. Coerenza uso-attivazione
for (i,k) in S:
    m.addConstr(z[i,k] <= y[i], name=f"link_{i}_{k}")

# 6. Massimo 4 fornitori attivi
m.addConstr(gp.quicksum(y[i] for i in suppliers) <= 4, name="max_suppliers")

# 7. Almeno uno tra A e B
m.addConstr(y['A'] + y['B'] >= 1, name="A_or_B")

# 8. Qualità media minima
for k in components:
    m.addConstr(
        gp.quicksum(quality[i,k]*x[i,k] for i in suppliers if (i,k) in cost) >= 95*demand[k],
        name=f"quality_{k}"
    )

# 9. Rischio totale massimo
m.addConstr(
    gp.quicksum(risk[i]*x[i,k] for (i,k) in S) <= 580,
    name="risk_total"
)

# Obiettivo
m.setObjective(
    gp.quicksum(cost[i,k]*x[i,k] for (i,k) in S) +
    gp.quicksum(fixed[i]*y[i] for i in suppliers),
    GRB.MINIMIZE
)

m.optimize()

status = m.Status
if status == GRB.OPTIMAL:
    variables = {}
    for (i,k) in S:
        variables[f"x_{i}_{k}"] = x[i,k].X
        variables[f"z_{i}_{k}"] = z[i,k].X
    for i in suppliers:
        variables[f"y_{i}"] = y[i].X
    obj = m.ObjVal
    print(f'SOLUTION_JSON={{"status":"OPTIMAL","objective":{obj},"variables":{variables}}}')
else:
    print(f'SOLUTION_JSON={{"status":"{status}","objective":null,"variables":{{}}}}')
```

## 4. Sintesi

Il modello MILP seleziona per ciascun componente (C1, C2, C3) almeno due fornitori tra i sei disponibili, rispettando quantità minime di 10 unità per combinazione attiva, capacità complessiva per fornitore, soglia di qualità media (≥95) e limite di rischio totale (≤580). Al massimo quattro fornitori possono essere attivati e almeno uno tra A e B deve esserlo. L'obiettivo minimizza la somma dei costi di acquisto variabili e dei costi fissi di attivazione dei fornitori scelti. Il codice Gurobi costruisce il modello a partire esclusivamente dai dati forniti nella traccia, risolve il problema e stampa un'unica riga `SOLUTION_JSON` con lo stato, il valore ottimo della funzione obiettivo e tutti i valori delle variabili decisionali (quantità x, indicatori di uso z, indicatori di attivazione y), inclusi quelli nulli.
