## 1. Insiemi, parametri e variabili decisionali

**Insiemi**  
- Nodi: \(N=\{\,S,T,A,B,C\,\}\)  
- Archi orientati:  
  \[
  E=\{(S,A),(S,B),(A,B),(A,C),(B,C),(B,T),(C,T)\}
  \]

**Parametri**  
Per ogni arco \(e=(i,j)\in E\):
- \(f_e\): costo fisso di attivazione;
- \(c_e\): costo per unità di flusso;
- \(u_e\): capacità massima.

Domanda da \(S\) a \(T\): \(D=40\).

**Variabili decisionali**  
- \(x_e \in \mathbb{Z}_{\ge 0}\): flusso sull’arco \(e\), con \(0 \le x_e \le u_e\);
- \(y_e \in \{0,1\}\): vale 1 se l’arco \(e\) viene attivato, 0 altrimenti.

---

## 2. Formulazione matematica

\[
\min \sum_{e\in E} \bigl(f_e y_e + c_e x_e\bigr)
\]

soggetto a:

\[
\sum_{e\in \delta^+(S)} x_e = 40
\]

\[
\sum_{e\in \delta^-(T)} x_e = 40
\]

\[
\sum_{e\in \delta^+(n)} x_e = \sum_{e\in \delta^-(n)} x_e
\qquad \forall n\in \{A,B,C\}
\]

\[
x_e \le u_e y_e
\qquad \forall e\in E
\]

\[
x_e \in \mathbb{Z}_{\ge 0},\qquad y_e\in\{0,1\}
\qquad \forall e\in E
\]

dove \(\delta^+(n)\) sono gli archi uscenti da \(n\) e \(\delta^-(n)\) quelli entranti.

---

## 3. Codice Python eseguibile con Gurobi

```python
import gurobipy as gp
from gurobipy import GRB
import json

arcs = [
    ("S", "A", 40, 2, 30),
    ("S", "B", 35, 3, 35),
    ("A", "B", 15, 1, 15),
    ("A", "C", 30, 2, 25),
    ("B", "C", 18, 2, 20),
    ("B", "T", 45, 4, 25),
    ("C", "T", 38, 2, 35),
]

nodes = ["S", "A", "B", "C", "T"]
E = [(i, j) for i, j, _, _, _ in arcs]

f = {(i, j): f for i, j, f, _, _ in arcs}
c = {(i, j): c for i, j, _, c, _ in arcs}
u = {(i, j): u for i, j, _, _, u in arcs}

m = gp.Model("rete_distributiva")
m.Params.OutputFlag = 0

x = {}
y = {}

for (i, j) in E:
    x[(i, j)] = m.addVar(
        vtype=GRB.INTEGER,
        lb=0,
        ub=u[(i, j)],
        name=f"x_{i}{j}"
    )
    y[(i, j)] = m.addVar(
        vtype=GRB.BINARY,
        name=f"y_{i}{j}"
    )

m.setObjective(
    sum(f[e] * y[e] + c[e] * x[e] for e in E),
    GRB.MINIMIZE
)

balance = {"S": 40, "A": 0, "B": 0, "C": 0, "T": -40}

for n in nodes:
    m.addConstr(
        sum(x[e] for e in E if e[0] == n) -
        sum(x[e] for e in E if e[1] == n) == balance[n],
        name=f"balance_{n}"
    )

for e in E:
    m.addConstr(x[e] <= u[e] * y[e], name=f"link_{e[0]}{e[1]}")

m.optimize()

status_names = {
    GRB.OPTIMAL: "OPTIMAL",
    GRB.INFEASIBLE: "INFEASIBLE",
    GRB.UNBOUNDED: "UNBOUNDED",
}

status = status_names.get(m.Status, f"STATUS_{m.Status}")

if status == "OPTIMAL":
    result = {
        "status": status,
        "objective": m.ObjVal,
        "variables": {v.VarName: v.X for v in m.getVars()},
    }
else:
    result = {
        "status": status,
        "objective": None,
        "variables": {},
    }

print("SOLUTION_JSON=" + json.dumps(result, separators=(",", ":")))
```

---

## 4. Sintesi della soluzione

Il solver termina con stato **OPTIMAL** e costo ottimo **443.0**.

Flusso ottimale:
- \(x_{SA}=25\), \(x_{SB}=15\);
- \(x_{AC}=25\);
- \(x_{BT}=15\), \(x_{CT}=25\);
- \(x_{AB}=0\), \(x_{BC}=0\).

Archi attivati:
- \(S\to A\), \(S\to B\), \(A\to C\), \(B\to T\), \(C\to T\).

Gli archi \(A\to B\) e \(B\to C\) non vengono attivati. La soluzione usa 25 unità sul percorso variabile più economico \(S\to A\to C\to T\) e le restanti 15 unità su \(S\to B\to T\).
