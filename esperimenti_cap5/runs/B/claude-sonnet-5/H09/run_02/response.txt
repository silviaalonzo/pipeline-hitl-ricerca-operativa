# H09 — Produzione e scorte multi-prodotto con straordinario

## 1. Insiemi, parametri e variabili decisionali

**Insiemi**
- $P = \{A, B, C\}$ — prodotti
- $T = \{1, 2, 3, 4, 5, 6\}$ — periodi
- $t_0 = 0$ — periodo fittizio iniziale (scorta iniziale nulla)

**Parametri**
- $d_{p,t}$ — domanda del prodotto $p$ nel periodo $t$
- $c_{p,t}$ — costo unitario di produzione
- $s_p$ — costo di setup del prodotto $p$
- $h_p$ — costo unitario di mantenimento a scorta
- $r_p$ — ore richieste per unità prodotta
- $L_p$ — lotto minimo di produzione
- $Cap_t$ — capacità oraria base nel periodo $t$
- $OT^{max} = 20$ — ore massime di straordinario per periodo
- $c^{OT} = 18$ — costo unitario dello straordinario
- $InvMax = 40$ — scorta totale massima di fine periodo
- $Fin_p = 2$ — scorta minima finale richiesta per ogni prodotto
- $N_t = 3$ se $t=1$, altrimenti $N_t = 2$ — massimo numero di setup attivi nel periodo
- $M_p = \sum_{t\in T} d_{p,t} + Fin_p$ — big-M per il linking produzione/setup

**Variabili decisionali**
- $x_{p,t} \ge 0,\ \text{intera}$ — quantità prodotta di $p$ nel periodo $t$
- $I_{p,t} \ge 0,\ \text{intera}$ — scorta di $p$ a fine periodo $t$ ($I_{p,0}=0$)
- $y_{p,t} \in \{0,1\}$ — indicatore di setup (produzione attiva) di $p$ nel periodo $t$
- $O_t \ge 0,\ \text{continua}$ — ore di straordinario usate nel periodo $t$

## 2. Formulazione matematica

$$
\min \; \sum_{p\in P}\sum_{t\in T} c_{p,t}\,x_{p,t}
+ \sum_{p\in P}\sum_{t\in T} s_p\,y_{p,t}
+ \sum_{p\in P}\sum_{t\in T} h_p\,I_{p,t}
+ \sum_{t\in T} c^{OT}\,O_t
$$

soggetto a:

**Bilancio di magazzino**
$$
I_{p,t} = I_{p,t-1} + x_{p,t} - d_{p,t} \qquad \forall p\in P,\ t\in T
$$
$$
I_{p,0} = 0 \qquad \forall p\in P
$$

**Scorta finale minima**
$$
I_{p,6} \ge Fin_p \qquad \forall p\in P
$$

**Capacità di magazzino totale**
$$
\sum_{p\in P} I_{p,t} \le InvMax \qquad \forall t\in T
$$

**Linking produzione–setup e lotto minimo**
$$
x_{p,t} \le M_p\, y_{p,t} \qquad \forall p\in P,\ t\in T
$$
$$
x_{p,t} \ge L_p\, y_{p,t} \qquad \forall p\in P,\ t\in T
$$

**Numero massimo di setup attivi per periodo**
$$
\sum_{p\in P} y_{p,t} \le N_t \qquad \forall t\in T
$$

**Capacità produttiva (con straordinario)**
$$
\sum_{p\in P} r_p\, x_{p,t} \le Cap_t + O_t \qquad \forall t\in T
$$
$$
0 \le O_t \le OT^{max} \qquad \forall t\in T
$$

**Dominio**
$$
x_{p,t}, I_{p,t} \in \mathbb{Z}_{\ge 0}, \quad y_{p,t}\in\{0,1\}, \quad O_t \in \mathbb{R}_{\ge 0}
$$

## 3. Codice Python (gurobipy)

```python
import gurobipy as gp
from gurobipy import GRB
import json

# --- Dati ---
P = ['A', 'B', 'C']
T = [1, 2, 3, 4, 5, 6]

d = {
    ('A',1):12, ('A',2):18, ('A',3):14, ('A',4):20, ('A',5):16, ('A',6):19,
    ('B',1):10, ('B',2):9,  ('B',3):15, ('B',4):12, ('B',5):17, ('B',6):14,
    ('C',1):8,  ('C',2):11, ('C',3):10, ('C',4):13, ('C',5):9,  ('C',6):15,
}

c = {
    ('A',1):7,  ('A',2):8,  ('A',3):9,  ('A',4):7,  ('A',5):10, ('A',6):8,
    ('B',1):9,  ('B',2):8,  ('B',3):8,  ('B',4):10, ('B',5):7,  ('B',6):9,
    ('C',1):11, ('C',2):10, ('C',3):12, ('C',4):9,  ('C',5):11, ('C',6):8,
}

setup = {'A':35, 'B':40, 'C':45}
hold  = {'A':2,  'B':2,  'C':3}
hours = {'A':2,  'B':3,  'C':4}
lot   = {'A':5,  'B':4,  'C':3}

Cap = {1:120, 2:115, 3:125, 4:110, 5:120, 6:115}

OT_max = 20
OT_cost = 18
InvMax = 40
FinMin = 2

Nsetup = {t: (3 if t == 1 else 2) for t in T}

# Big-M per prodotto: somma totale della domanda + scorta finale minima
M = {p: sum(d[p, t] for t in T) + FinMin for p in P}

# --- Modello ---
m = gp.Model("H09_multiprod")

x = m.addVars(P, T, vtype=GRB.INTEGER, lb=0, name="x")
I = m.addVars(P, [0] + T, vtype=GRB.INTEGER, lb=0, name="I")
y = m.addVars(P, T, vtype=GRB.BINARY, name="y")
O = m.addVars(T, vtype=GRB.CONTINUOUS, lb=0, ub=OT_max, name="O")

# Scorta iniziale nulla
for p in P:
    m.addConstr(I[p, 0] == 0, name=f"init_{p}")

# Bilancio di magazzino
for p in P:
    for t in T:
        m.addConstr(I[p, t] == I[p, t-1] + x[p, t] - d[p, t], name=f"bal_{p}_{t}")

# Scorta finale minima
for p in P:
    m.addConstr(I[p, 6] >= FinMin, name=f"finmin_{p}")

# Capacità totale di magazzino
for t in T:
    m.addConstr(gp.quicksum(I[p, t] for p in P) <= InvMax, name=f"invcap_{t}")

# Linking produzione-setup e lotto minimo
for p in P:
    for t in T:
        m.addConstr(x[p, t] <= M[p] * y[p, t], name=f"link_{p}_{t}")
        m.addConstr(x[p, t] >= lot[p] * y[p, t], name=f"lotmin_{p}_{t}")

# Numero massimo di setup attivi per periodo
for t in T:
    m.addConstr(gp.quicksum(y[p, t] for p in P) <= Nsetup[t], name=f"nsetup_{t}")

# Capacità produttiva con straordinario
for t in T:
    m.addConstr(
        gp.quicksum(hours[p] * x[p, t] for p in P) <= Cap[t] + O[t],
        name=f"cap_{t}"
    )

# --- Funzione obiettivo ---
obj = (
    gp.quicksum(c[p, t] * x[p, t] for p in P for t in T)
    + gp.quicksum(setup[p] * y[p, t] for p in P for t in T)
    + gp.quicksum(hold[p] * I[p, t] for p in P for t in T)
    + gp.quicksum(OT_cost * O[t] for t in T)
)
m.setObjective(obj, GRB.MINIMIZE)

m.optimize()

# --- Output ---
status_map = {
    GRB.OPTIMAL: "OPTIMAL",
    GRB.INFEASIBLE: "INFEASIBLE",
    GRB.UNBOUNDED: "UNBOUNDED",
}
status = status_map.get(m.status, str(m.status))

variables = {}
objective = None

if m.status == GRB.OPTIMAL:
    objective = m.ObjVal
    for p in P:
        for t in T:
            variables[f"x_{p}_{t}"] = round(x[p, t].X, 4)
            variables[f"I_{p}_{t}"] = round(I[p, t].X, 4)
            variables[f"y_{p}_{t}"] = round(y[p, t].X, 4)
    for t in T:
        variables[f"O_{t}"] = round(O[t].X, 4)

result = {
    "status": status,
    "objective": objective,
    "variables": variables
}

print("SOLUTION_JSON=" + json.dumps(result))
```

## 4. Sintesi della soluzione

Il modello determina il piano di produzione, i livelli di scorta, i setup attivati e l'uso di straordinario per i tre prodotti nei sei periodi, minimizzando la somma di:
- costi di produzione variabili,
- costi fissi di setup,
- costi di mantenimento a scorta,
- costi dello straordinario.

Le decisioni rispettano: soddisfacimento della domanda senza arretrati, scorta iniziale nulla, scorta finale minima di 2 unità per prodotto, vincolo di lotto minimo legato al setup, limite di massimo 3 setup nel primo periodo e 2 nei periodi successivi, capacità produttiva (base + straordinario, limitato a 20 ore/periodo al costo di 18/ora) e tetto di 40 unità sulla scorta totale di fine periodo.

Il codice Gurobi risolve il MILP e stampa un'unica riga `SOLUTION_JSON` contenente lo stato del solver (atteso `OPTIMAL`), il valore ottimo della funzione obiettivo e tutti i valori delle variabili decisionali ($x_{p,t}$, $I_{p,t}$, $y_{p,t}$, $O_t$), incluse quelle nulle.
