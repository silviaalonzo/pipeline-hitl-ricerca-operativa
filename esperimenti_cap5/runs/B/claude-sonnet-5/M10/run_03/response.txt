# M10 — Progettazione di una rete distributiva

## 1. Insiemi, parametri e variabili decisionali

**Insiemi**
- Nodi: $N = \{S, A, B, C, T\}$
- Archi: $E = \{(S,A), (S,B), (A,B), (A,C), (B,C), (B,T), (C,T)\}$

**Parametri**
- $f_{ij}$: costo fisso di attivazione dell'arco $(i,j) \in E$
- $c_{ij}$: costo unitario di trasporto sull'arco $(i,j)$
- $u_{ij}$: capacità dell'arco $(i,j)$
- $D = 40$: domanda totale da inviare da $S$ a $T$

| Arco | $f_{ij}$ | $c_{ij}$ | $u_{ij}$ |
|---|---|---|---|
| S→A | 40 | 2 | 30 |
| S→B | 35 | 3 | 35 |
| A→B | 15 | 1 | 15 |
| A→C | 30 | 2 | 25 |
| B→C | 18 | 2 | 20 |
| B→T | 45 | 4 | 25 |
| C→T | 38 | 2 | 35 |

**Variabili decisionali**
- $x_{ij} \in \mathbb{Z}_{\ge 0}$: flusso intero sull'arco $(i,j) \in E$
- $y_{ij} \in \{0,1\}$: 1 se l'arco $(i,j)$ è attivato (flusso > 0), 0 altrimenti

## 2. Formulazione matematica

$$\min \sum_{(i,j) \in E} \left( f_{ij}\, y_{ij} + c_{ij}\, x_{ij} \right)$$

**Vincoli**

Conservazione del flusso nei nodi intermedi:
$$x_{SA} = x_{AB} + x_{AC} \quad \text{(nodo A)}$$
$$x_{SB} + x_{AB} = x_{BC} + x_{BT} \quad \text{(nodo B)}$$
$$x_{AC} + x_{BC} = x_{CT} \quad \text{(nodo C)}$$

Bilancio globale (offerta/domanda):
$$x_{SA} + x_{SB} = D$$
$$x_{BT} + x_{CT} = D$$

Attivazione e capacità (per ogni arco $(i,j) \in E$):
$$x_{ij} \le u_{ij}\, y_{ij}$$

Dominio:
$$x_{ij} \in \mathbb{Z}_{\ge 0}, \quad y_{ij} \in \{0,1\} \quad \forall (i,j) \in E$$

## 3. Codice Python con gurobipy

```python
import gurobipy as gp
from gurobipy import GRB
import json

# --- Dati ---
arcs = [
    ("S","A"), ("S","B"),
    ("A","B"), ("A","C"),
    ("B","C"), ("B","T"),
    ("C","T")
]

fixed_cost = {
    ("S","A"): 40, ("S","B"): 35,
    ("A","B"): 15, ("A","C"): 30,
    ("B","C"): 18, ("B","T"): 45,
    ("C","T"): 38
}

unit_cost = {
    ("S","A"): 2, ("S","B"): 3,
    ("A","B"): 1, ("A","C"): 2,
    ("B","C"): 2, ("B","T"): 4,
    ("C","T"): 2
}

capacity = {
    ("S","A"): 30, ("S","B"): 35,
    ("A","B"): 15, ("A","C"): 25,
    ("B","C"): 20, ("B","T"): 25,
    ("C","T"): 35
}

D = 40  # domanda totale da S a T

# --- Modello ---
m = gp.Model("rete_distributiva")

x = m.addVars(arcs, vtype=GRB.INTEGER, lb=0, name="x")
y = m.addVars(arcs, vtype=GRB.BINARY, name="y")

# Funzione obiettivo
m.setObjective(
    gp.quicksum(fixed_cost[a]*y[a] + unit_cost[a]*x[a] for a in arcs),
    GRB.MINIMIZE
)

# Vincoli di capacità/attivazione
for a in arcs:
    m.addConstr(x[a] <= capacity[a]*y[a], name=f"cap_{a[0]}{a[1]}")

# Bilancio nodi intermedi
m.addConstr(x[("S","A")] == x[("A","B")] + x[("A","C")], name="flow_A")
m.addConstr(x[("S","B")] + x[("A","B")] == x[("B","C")] + x[("B","T")], name="flow_B")
m.addConstr(x[("A","C")] + x[("B","C")] == x[("C","T")], name="flow_C")

# Bilancio globale S e T
m.addConstr(x[("S","A")] + x[("S","B")] == D, name="supply_S")
m.addConstr(x[("B","T")] + x[("C","T")] == D, name="demand_T")

m.optimize()

# --- Estrazione risultati ---
status_map = {
    GRB.OPTIMAL: "OPTIMAL",
    GRB.INFEASIBLE: "INFEASIBLE",
    GRB.UNBOUNDED: "UNBOUNDED"
}
status = status_map.get(m.status, str(m.status))

variables = {}
objective = None

if m.status == GRB.OPTIMAL:
    objective = m.objVal
    for a in arcs:
        vname_x = f"x_{a[0]}{a[1]}"
        vname_y = f"y_{a[0]}{a[1]}"
        variables[vname_x] = float(round(x[a].X))
        variables[vname_y] = float(round(y[a].X))

    # Stampa dettagliata (facoltativa, per leggibilità)
    print(f"Stato solver: {status}")
    print(f"Valore ottimo: {objective}")
    print("Decisioni non nulle:")
    for a in arcs:
        if x[a].X > 1e-6:
            print(f"  x_{a[0]}{a[1]} = {round(x[a].X)}  (y_{a[0]}{a[1]} = {round(y[a].X)})")
else:
    print(f"Stato solver: {status}")

print("SOLUTION_JSON=" + json.dumps({
    "status": status,
    "objective": objective,
    "variables": variables
}))
```

## 4. Sintesi della soluzione

Il modello MILP determina simultaneamente **quali archi attivare** (variabili $y_{ij}$) e **quanto flusso instradare** su ciascuno di essi (variabili $x_{ij}$), minimizzando la somma dei costi fissi di attivazione e dei costi variabili di trasporto, nel rispetto delle capacità e della conservazione del flusso ai nodi intermedi $A$, $B$, $C$.

La soluzione ottima individuata da Gurobi instrada le 40 unità richieste sfruttando i percorsi a minor costo marginale compatibili con le capacità disponibili (tipicamente una combinazione dei percorsi S→A→C→T e S→B→T/S→B→C→T), attivando solo gli archi effettivamente utilizzati e riportando il costo totale minimo comprensivo di costi fissi e variabili. Il risultato esatto (valore obiettivo e flussi sui singoli archi) è riportato nella riga `SOLUTION_JSON` prodotta dal programma.
