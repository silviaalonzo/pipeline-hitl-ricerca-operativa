# M10 — Progettazione di una rete distributiva

## 1. Insiemi, parametri e variabili decisionali

**Insiemi**
- $N = \{S, A, B, C, T\}$ : nodi della rete
- $E = \{(S,A),(S,B),(A,B),(A,C),(B,C),(B,T),(C,T)\}$ : archi attivabili

**Parametri** (per ogni arco $(i,j)\in E$)
- $f_{ij}$ : costo fisso di attivazione dell'arco
- $c_{ij}$ : costo per unità di flusso trasportato sull'arco
- $u_{ij}$ : capacità massima dell'arco
- $D = 40$ : domanda totale da inviare da $S$ a $T$

| Arco | $f_{ij}$ | $c_{ij}$ | $u_{ij}$ |
|---|---|---|---|
| S→A | 40 | 2 | 30 |
| S→B | 35 | 3 | 35 |
| A→B | 15 | 1 | 15 |
| A→C | 30 | 2 | 25 |
| B→C | 18 | 2 | 20 |
| B→T | 45 | 4 | 25 |
| C→T | 38 | 2 | 35 |

**Variabili decisionali**
- $x_{ij} \in \mathbb{Z}_{\ge 0}$ : flusso intero sull'arco $(i,j)\in E$
- $y_{ij} \in \{0,1\}$ : 1 se l'arco $(i,j)$ è attivato, 0 altrimenti

## 2. Formulazione matematica

$$
\min \sum_{(i,j)\in E} f_{ij}\, y_{ij} + \sum_{(i,j)\in E} c_{ij}\, x_{ij}
$$

soggetto a:

**Capacità legata all'attivazione**
$$
x_{ij} \le u_{ij}\, y_{ij} \qquad \forall (i,j)\in E
$$

**Conservazione del flusso al nodo S (offerta)**
$$
x_{SA} + x_{SB} = D
$$

**Conservazione del flusso al nodo A**
$$
x_{SA} = x_{AB} + x_{AC}
$$

**Conservazione del flusso al nodo B**
$$
x_{SB} + x_{AB} = x_{BC} + x_{BT}
$$

**Conservazione del flusso al nodo C**
$$
x_{AC} + x_{BC} = x_{CT}
$$

**Conservazione del flusso al nodo T (domanda)**
$$
x_{BT} + x_{CT} = D
$$

**Dominio**
$$
x_{ij} \in \mathbb{Z}_{\ge 0},\qquad y_{ij}\in\{0,1\} \qquad \forall (i,j)\in E
$$

## 3. Codice Python (gurobipy)

```python
import gurobipy as gp
from gurobipy import GRB
import json

# --- Dati ---
arcs = [
    ("S","A"), ("S","B"), ("A","B"),
    ("A","C"), ("B","C"), ("B","T"), ("C","T")
]

fixed_cost = {
    ("S","A"): 40, ("S","B"): 35, ("A","B"): 15,
    ("A","C"): 30, ("B","C"): 18, ("B","T"): 45, ("C","T"): 38
}

unit_cost = {
    ("S","A"): 2, ("S","B"): 3, ("A","B"): 1,
    ("A","C"): 2, ("B","C"): 2, ("B","T"): 4, ("C","T"): 2
}

capacity = {
    ("S","A"): 30, ("S","B"): 35, ("A","B"): 15,
    ("A","C"): 25, ("B","C"): 20, ("B","T"): 25, ("C","T"): 35
}

DEMAND = 40

# --- Modello ---
m = gp.Model("Rete_Distributiva_M10")

x = m.addVars(arcs, vtype=GRB.INTEGER, lb=0, name="x")
y = m.addVars(arcs, vtype=GRB.BINARY, name="y")

# Funzione obiettivo
m.setObjective(
    gp.quicksum(fixed_cost[a]*y[a] + unit_cost[a]*x[a] for a in arcs),
    GRB.MINIMIZE
)

# Capacità legata all'attivazione
for a in arcs:
    m.addConstr(x[a] <= capacity[a]*y[a], name=f"cap_{a}")

# Conservazione del flusso
m.addConstr(x[("S","A")] + x[("S","B")] == DEMAND, name="flow_S")
m.addConstr(x[("S","A")] == x[("A","B")] + x[("A","C")], name="flow_A")
m.addConstr(x[("S","B")] + x[("A","B")] == x[("B","C")] + x[("B","T")], name="flow_B")
m.addConstr(x[("A","C")] + x[("B","C")] == x[("C","T")], name="flow_C")
m.addConstr(x[("B","T")] + x[("C","T")] == DEMAND, name="flow_T")

m.optimize()

# --- Output ---
status_map = {
    GRB.OPTIMAL: "OPTIMAL",
    GRB.INFEASIBLE: "INFEASIBLE",
    GRB.UNBOUNDED: "UNBOUNDED"
}
status = status_map.get(m.Status, str(m.Status))

if m.Status == GRB.OPTIMAL:
    variables = {}
    for a in arcs:
        varname_x = f"x_{a[0]}{a[1]}"
        varname_y = f"y_{a[0]}{a[1]}"
        variables[varname_x] = float(round(x[a].X))
        variables[varname_y] = float(round(y[a].X))
    result = {
        "status": status,
        "objective": float(round(m.ObjVal, 2)),
        "variables": variables
    }
else:
    result = {
        "status": status,
        "objective": None,
        "variables": {}
    }

print("SOLUTION_JSON=" + json.dumps(result))
```

## 4. Sintesi della soluzione

Il modello MILP determina il sottoinsieme di archi da attivare e il flusso intero da instradare su ciascun arco per inviare 40 unità da S a T minimizzando la somma dei costi fissi di attivazione e dei costi variabili di trasporto.

La soluzione ottima attiva gli archi **S→A**, **A→C**, **C→T**, **S→B**, **B→T** (5 archi su 7), instradando:
- 25 unità sul percorso S→A→C→T (costo marginale 6/unità, il più economico)
- 15 unità sul percorso S→B→T (saturando la capacità residua in modo ottimale)

Gli archi **A→B** e **B→C** restano non attivati poiché il loro utilizzo comporterebbe costi fissi aggiuntivi non compensati da risparmi sui costi variabili.

Il costo totale ottimo risultante è **443** (188 di costi fissi + 255 di costi variabili di trasporto), come confermato dall'esecuzione del solver Gurobi.
