# 1. Insiemi, parametri e variabili decisionali

**Insiemi**
- $I = \{1,2,\dots,8\}$: insieme dei progetti.
- $D = \{1,3,7\} \subset I$: sottoinsieme dei progetti "digitali".

**Parametri**
- $v_i$: valore del progetto $i \in I$.
- $b_i$: budget richiesto dal progetto $i \in I$.
- $p_i$: personale richiesto dal progetto $i \in I$.
- $B = 100$: budget disponibile.
- $P = 18$: personale disponibile.

| i | v_i | b_i | p_i |
|---|-----|-----|-----|
| 1 | 30 | 20 | 4 |
| 2 | 24 | 18 | 3 |
| 3 | 35 | 27 | 5 |
| 4 | 28 | 24 | 4 |
| 5 | 33 | 22 | 4 |
| 6 | 26 | 19 | 3 |
| 7 | 38 | 30 | 5 |
| 8 | 21 | 15 | 2 |

**Variabili decisionali**
- $x_i \in \{0,1\}$ per ogni $i \in I$: $x_i = 1$ se il progetto $i$ viene selezionato, $0$ altrimenti.

# 2. Formulazione matematica

**Funzione obiettivo**

$$\max \; Z = \sum_{i \in I} v_i x_i$$

**Vincoli**

Budget:
$$\sum_{i \in I} b_i x_i \le B$$

Personale:
$$\sum_{i \in I} p_i x_i \le P$$

Dipendenza P5 richiede P2:
$$x_5 \le x_2$$

Dipendenza P7 richiede P3:
$$x_7 \le x_3$$

Incompatibilità P4 e P6:
$$x_4 + x_6 \le 1$$

Almeno un progetto digitale tra P1, P3, P7:
$$x_1 + x_3 + x_7 \ge 1$$

Almeno tre progetti complessivi:
$$\sum_{i \in I} x_i \ge 3$$

Dominio:
$$x_i \in \{0,1\} \quad \forall i \in I$$

# 3. Codice Python con gurobipy

```python
import gurobipy as gp
from gurobipy import GRB
import json

# Dati
progetti = [1,2,3,4,5,6,7,8]
valore = {1:30, 2:24, 3:35, 4:28, 5:33, 6:26, 7:38, 8:21}
budget = {1:20, 2:18, 3:27, 4:24, 5:22, 6:19, 7:30, 8:15}
personale = {1:4, 2:3, 3:5, 4:4, 5:4, 6:3, 7:5, 8:2}

B_max = 100
P_max = 18
digitali = [1,3,7]

# Modello
m = gp.Model("Selezione_Portafoglio_Progetti")

# Variabili
x = m.addVars(progetti, vtype=GRB.BINARY, name="x")

# Obiettivo
m.setObjective(gp.quicksum(valore[i]*x[i] for i in progetti), GRB.MAXIMIZE)

# Vincoli
m.addConstr(gp.quicksum(budget[i]*x[i] for i in progetti) <= B_max, name="Budget")
m.addConstr(gp.quicksum(personale[i]*x[i] for i in progetti) <= P_max, name="Personale")

m.addConstr(x[5] <= x[2], name="P5_richiede_P2")
m.addConstr(x[7] <= x[3], name="P7_richiede_P3")
m.addConstr(x[4] + x[6] <= 1, name="P4_P6_incompatibili")
m.addConstr(x[1] + x[3] + x[7] >= 1, name="Almeno_un_digitale")
m.addConstr(gp.quicksum(x[i] for i in progetti) >= 3, name="Almeno_tre_progetti")

# Risoluzione
m.optimize()

# Output risultati
status = m.Status
result = {"status": None, "objective": None, "variables": {}}

if status == GRB.OPTIMAL:
    result["status"] = "OPTIMAL"
    result["objective"] = round(m.ObjVal, 2)
    for i in progetti:
        result["variables"][f"x_{i}"] = round(x[i].X, 2)
else:
    result["status"] = str(status)
    result["objective"] = None
    result["variables"] = {}

print("SOLUTION_JSON=" + json.dumps(result))
```

# 4. Sintesi della soluzione

Il modello IP binario seleziona il sottoinsieme di progetti che massimizza il valore complessivo rispettando i vincoli di budget (≤100), personale (≤18 unità), le dipendenze logiche (P5→P2, P7→P3), l'incompatibilità P4-P6, il requisito di almeno un progetto digitale (P1, P3 o P7) e la cardinalità minima di 3 progetti.

Risolvendo con Gurobi, il solver individua la combinazione ottima di progetti che:
- Rispetta tutti i vincoli di risorsa e logici;
- Massimizza il valore totale del portafoglio.

Lo stato del solver, il valore ottimo della funzione obiettivo e le decisioni $x_i$ (0 o 1) per ciascun progetto vengono riportati nella riga `SOLUTION_JSON` stampata a console, che indica esplicitamente quali progetti risultano selezionati (valore 1) e quali esclusi (valore 0) nella soluzione ottima.
